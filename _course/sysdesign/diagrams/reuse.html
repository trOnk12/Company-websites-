1. A first request on a new connection: a TCP handshake, then a TLS handshake, each one round trip, then the request itself. Three trips.

  2. Connection reuse: the connection stays open, and the next request goes straight over it.

  3. No handshakes this time: one round trip. Predict: what if the screen needs several requests at once?

  4. HTTP/2 sends them all at once over that one connection: multiplexing. One shared OkHttpClient keeps it open for later requests.
