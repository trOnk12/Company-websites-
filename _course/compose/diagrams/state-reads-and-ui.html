1. The shared screen keeps the bookmark count in snapshot state. It calls a header that shows the count, and a list of saved items.

  2. The screen reads count.value itself and passes the number 2 down to the header. So the state read happens in the screen's group.

  3. A tap changes the count to 3. Predict: which group does Compose mark?

  4. The screen's, because that's where the read happened. The whole screen runs again; the header gets 3, and the list is skipped only because its arguments are equal.

  5. Pass a lambda that reads the count, and call it inside the header. Now the read happens in the header, and a tap marks only the header: deferring a read.
