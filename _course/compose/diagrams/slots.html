1. The first run of these calls builds the composition: a tree of groups, nested the way the calls nest. It stays after the calls return.

  2. Text and Button also leave a node each: a real UI element the screen is made of. Greeting and Counter leave only groups.

  3. Groups keep values in slots: the arguments they got last time, and what they asked to remember, like Counter's count.

  4. The runtime stores it all, groups and slots, in call order in one long slot table. Predict: on the next run, how does Counter find its 0 again?

  5. The calls come in the same order, from the same places in the code, so Counter reaches the same spot and finds its slot. Its place in the code is its call site.
