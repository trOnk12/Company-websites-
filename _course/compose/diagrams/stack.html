1. At the bottom, the Compose runtime: the composition, the slot table, snapshot state and the Recomposer from puzzles 0 to 4. It never looks inside a node.

  2. To change the tree, the runtime calls an Applier: insert this node at this index, move, remove. Compose UI plugs one in for its LayoutNodes, and does layout and drawing.

  3. foundation builds on Compose UI: Row, Column, LazyColumn, gestures. Building blocks with no look of their own.

  4. Material sits on top: a design system, ready-made components with colours, type and shapes. Predict: which layers hold code written for iOS?

  5. All four, counted in Kotlin files. Compose UI's iosMain is the big one: the hosting controller, the keyboard, accessibility. The runtime's 8 serve every native target; material3's 2, every Apple one.

  6. Much more sits in skikoMain, shared by iOS, desktop and web, including the Applier iOS uses: DefaultUiApplier. Android plugs in UiApplier instead.
