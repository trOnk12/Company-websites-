1. The main thread works from an in-tray: its message queue. Draw the screen, run onCreate, handle a touch (a tap): each is a message, waiting its turn.

  2. A Binder thread receives "resume" from the town hall. It doesn't touch the screen: it drops the message at the end of the queue with a Handler: an object tied to the main thread's queue that drops messages into it. Predict: when will it run?

  3. When its turn comes. The main thread takes the first message, runs it to the end, and the line moves up: one at a time, in order. This endless take, run, repeat is the Looper.
