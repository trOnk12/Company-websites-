1. Phones use different CPUs, but you ship one APK. So your Kotlin isn't compiled to machine code at build time. It becomes DEX bytecode, an instruction format for Android.

  2. On the phone, ART (the Android Runtime) runs inside your app's own process. At first it can simply interpret the DEX: correct, but slow.

  3. Code that runs often ("hot" code) gets compiled to machine code just in time (JIT), while the app runs. ART also writes down which code was hot in a profile.

  4. Later, in the background, dex2oat uses that profile to compile the hot code ahead of time (AOT), so next time it starts fast. A Baseline Profile ships that list with your app, so users get the speed from the first launch.
