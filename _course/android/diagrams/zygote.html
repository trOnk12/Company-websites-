1. Starting ART and loading thousands of framework classes takes seconds. So at boot, Android starts one process, Zygote, does all of that once, and then waits.

  2. You tap an app icon. Zygote forks: it copies itself into a new process, which switches to your app's UID and loads your code. Everything else is already loaded, so it starts fast.

  3. Every app is forked the same way. They don't each get their own copy of the framework: a fork shares the parent's memory pages. Dozens of apps, one framework in RAM.

  4. Only when an app writes to a shared page does Linux make a private copy of that one page for it. This is called copy-on-write.
