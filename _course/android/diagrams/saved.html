1. The user switches apps, so your Activity is stopped. The draft is a value your app chose to save (see the code below), so it's packed into a Bundle, a small map of simple values. Binder carries it to system_server: the screen's saved state.

  2. Memory runs short, and Android ends your process in the background: process death. The ViewModel and every other object go with it. Predict: the user comes back. Is the draft still there?

  3. Yes. A new process starts, and system_server hands the Bundle back by Binder. The new Activity reads the draft from it.

  4. But if the user closes the screen for good with Back, there's nothing to come back to, so system_server throws the saved state away.
