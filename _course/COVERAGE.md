# What can a learner independently demonstrate?

Editorial review, 21 November 2026. The scope is the 13 catalog courses, their practice chapters and final projects, and the executable fixtures under `labs/`. Each row selects one professional task small enough for a second engineer to reproduce. The final column names the evidence still needed to assess that task. A worked solution establishes what the author can explain. An independent run establishes what a learner can reproduce, diagnose and defend.

| Course | What the current material exercises | Next assessment and acceptance evidence |
| --- | --- | --- |
| Android foundations | The [trail-note project](android/practicum.json) traces activity recreation and recovery after process death. The background-work chapter follows a persistent worker through a retry. | **Test a constrained background upload on Android.** Supply an emulator-ready fixture. Hold the network constraint, release it, inject a retry and assert the recorded upload effect occurred once. Retain the worker states and durable records. [Android WorkManager integration testing](https://developer.android.com/develop/background-work/background-tasks/testing/persistent/integration-testing) |
| Backend operations | The [bookmark service lab](../labs/bookmark-service/README.md) exercises relational writes, image creation and rollout. The [final project](backend-ops/practicum.json) checks conflict handling across releases. | **Restore PostgreSQL to the moment before an accidental deletion.** Provide a disposable database, a base backup and archived write-ahead logs. Recover into a second instance, verify one committed row on either side of the target and record elapsed recovery time. [PostgreSQL point-in-time recovery](https://www.postgresql.org/docs/17/continuous-archiving.html) |
| Bluetooth Low Energy | The [strap project](ble/practicum.json) separates local notification delivery, the remote subscription and the first measurement. The practice chapter traces asynchronous operation completion. | **Recover live notifications after a disconnect.** Supply a programmable test peripheral or a reproducible two-device fixture. Interrupt the link during subscription, reconnect and record the first fresh measurement plus the number of callbacks per measurement. [Android BLE data transfer](https://developer.android.com/develop/connectivity/bluetooth/ble/transfer-ble-data) |
| Compose Multiplatform | The [bookmark card project](compose/practicum.json) reasons about composition, native text input and the Clear action. | **Verify the same edit-and-clear flow with TalkBack and VoiceOver.** Supply one build per platform. Record focus order, the spoken control label, activation and the resulting field value. A mismatch should identify the responsible semantics or native-view boundary. [Compose Multiplatform accessibility](https://kotlinlang.org/docs/multiplatform/compose-accessibility.html) |
| iOS | The [practice material](ios/topics.json) distinguishes build targets, signing, distribution and sampled stacks. The project follows a stale result across screen lifetimes. | **Diagnose a crash from an archived release.** Supply a synthetic crash report and symbols for two builds. Select the matching symbols, recover the failing app frame and demonstrate why the other build cannot identify it. [Apple crash report symbolication](https://developer.apple.com/documentation/xcode/adding-identifiable-symbol-names-to-a-crash-report) |
| JVM internals | The [Java lab](../labs/jvm/README.md) executes local-variable, reference and atomic-update cases and proposes a pool-exhaustion investigation. The [diagnostics chapter](jvm/topics.json) reasons from threads and recordings. | **Distinguish lock contention from pool exhaustion in an unfamiliar process.** Provide two executable fault modes with the same slow-request symptom. Require a fresh thread dump or recording for each run, the decisive stack or event, and a repeat after changing one cause. [JDK 21 diagnostic tools](https://docs.oracle.com/en/java/javase/21/troubleshoot/diagnostic-tools.html) |
| Kotlin Multiplatform | The [Swift boundary project](kmp/practicum.json) assigns source sets and follows ownership across a callback. It invites inspection of a generated declaration. | **Deliver a versioned shared library to a clean Swift project.** Build and package a small framework, consume that artifact from a separate app and call one exported success and error path. Keep the package version, generated declaration and consumer build result. [Kotlin Swift package export](https://kotlinlang.org/docs/multiplatform/multiplatform-spm-export.html) |
| LLM applications | The [support-assistant project](llm/practicum.json) independently scores retrieval and answer support on four specified cases, including one unanswerable question. | **Detect an answer-quality regression automatically.** Supply a held-out labeled fixture and two sets of captured model outputs. Run one evaluator twice, identify the changed case, and show which predeclared retrieval or grounding criterion blocks release. [Anthropic evaluation design](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests) |
| Android performance | The [frame project](perf/practicum.json) distinguishes CPU running time from blocked time. Practice cases cover benchmark design, compilation and startup endpoints. | **Verify a performance fix on a release-like build.** Supply baseline and candidate variants plus a Macrobenchmark target. Run the same journey repeatedly on the same device, retain timing distributions and a trace from each variant, and defend one causal claim. [Android Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview) |
| Encryption and application security | The [security chapters](security/topics.json) cover key access, encrypted record formats, recovery and rotation. The final project traces a private receipt through TLS and an ownership decision. | **Recover a synthetic encrypted draft after its local key becomes unavailable.** Use a disposable Android fixture and test records. Record the successful round trip, the missing-key state after removal and the defined recovery behavior, including whether an unreadable record is preserved. [Android Keystore](https://developer.android.com/privacy-and-security/keystore) |
| Mobile system design | The [offline-edit project](sysdesign/practicum.json) tracks a durable pending operation through restart, reconnect and a lost response. | **Reconcile conflicting offline edits from two actual clients.** Give each client its own local store. Edit one record on both, reconnect in each order and inspect both local rows, queue entries and the server version. State which conflict policy explains the final state. [Android offline-first data layer](https://developer.android.com/topic/architecture/data-layer/offline-first) |
| Distributed system design | The [isolation lab](../labs/postgres-isolation/README.md) runs real competing database transactions. Practice chapters examine replica acknowledgments, overload and rebuilding a read model. | **Qualify the production failover policy.** The [two-server fixture](../labs/postgres-isolation/failover.py) now reproduces acknowledgement and promotion under two policies. Test automatic fencing and candidate selection during a network partition in the intended deployment, and verify single-writer ownership before restoring service. [PostgreSQL standby servers](https://www.postgresql.org/docs/17/warm-standby.html) |
| Transport protocols | The [slow-response project](transport/practicum.json) budgets network trips and traces the effects of loss on HTTP/2 and HTTP/3. | **Attribute a real request delay to a measured phase.** Provide a local TLS endpoint with a controllable response delay. Compare fresh and reused connections, record the negotiated protocol and timing boundaries, then identify which interval changes when the delay is introduced. [curl timing and connection metrics](https://curl.se/docs/manpage.html#-w) |
