1. Two binaries: the app's executable, which Xcode builds from Swift, and your Kotlin framework. Swift's calls into Kotlin still need addresses.

  2. A static library is joined at build time: Xcode's linker copies your Kotlin into the app's executable. One file reaches the phone.

  3. Predict: what if the library inside your framework isn't copied in?

  4. A dynamic library isn't copied in: it ships as its own file inside the app, next to the executable.

  5. Each time the app starts, the dynamic loader loads it and connects Swift's calls to its addresses.
