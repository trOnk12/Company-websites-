1. In a debug build, LLVM wrote object code for your module, and Ktor's comes ready from a cache. Your call into Ktor leaves the address open.

  2. The open call names its target by a symbol: the function's name in compiled code. Ktor's object code defines the same symbol.

  3. The linker joins the pieces into one binary and replaces each named call with an address. Predict: what's different in a release build?

  4. All the Kotlin arrives as one piece, merged before LLVM. Dead code elimination already dropped what nothing reaches, there, before LLVM.

  5. The linker still joins it into the binary, and its -dead_strip option trims a few more unused bits: a second, smaller cut.
