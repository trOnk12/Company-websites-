1. One change in commonMain: the compile stage rewrites one klib, quickly. Predict: how long does the link stage take?

  2. Much longer: it runs once per final binary, and most of it is LLVM optimizing and generating code.

  3. An XCFramework links every target in it. Xcode's embedAndSign task links only the one Xcode is building for.

  4. A release build uses link-time optimization: all modules optimized together in LLVM. It takes about ten times as long.

  5. A debug build reuses a compilation cache: libraries already compiled once, kept in ~/.konan, so their work isn't repeated.

  6. Size: an exported module comes in whole; the rest is trimmed. The smallBinary option asks LLVM to optimize release builds for size.
