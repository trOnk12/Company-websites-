1. A link task starts the link stage: once per final binary, it reads every klib, so the compiler sees the whole program at once.

  2. Kotlin/Native's back end translates all that IR into LLVM IR: lower level, closer to instructions, but still tied to no processor.

  3. It hands that to LLVM, shared compiler parts. Its optimizer rewrites the code to do the same work faster. Predict: what comes out for iosArm64?

  4. LLVM's code generator writes Arm instructions for the iPhone's processor: the native code from puzzle 0, at last.

  5. The same LLVM generates code for other processors too, and Apple's Clang compiler uses it. Kotlin writes none of that itself.
