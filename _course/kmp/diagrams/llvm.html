1. A release link task starts the link stage: once per final binary, it reads every klib, so the compiler sees the whole program at once.

  2. Kotlin/Native's back end translates all that IR into LLVM IR: lower level, already marked with the target, but not yet instructions.

  3. Kotlin's runtime joins here. It ships as LLVM IR in files, runtime.bc and the collector's, and is merged in with your program.

  4. It all goes to LLVM, shared compiler parts. Its optimizer rewrites the code to do the same work faster. Predict: what comes out for iosArm64?

  5. LLVM's code generator writes Arm instructions for the iPhone's processor: the native code from puzzle 0, at last.

  6. The same LLVM generates code for other processors too, and Apple's Clang compiler uses it. Kotlin writes none of that itself.
