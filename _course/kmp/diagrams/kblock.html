1. A shared module's build file has a kotlin { } block. The multiplatform plugin, a Gradle plugin like Android's, reads it.

  2. Each line declares a target. iOS takes two: iosArm64 for real iPhones, iosSimulatorArm64 for the simulator, the stand-in iPhone that runs on your Mac.

  3. Each target gets a platform source set of its own, named after it. Predict: when iosArm64 is built, which source sets go in?

  4. Its own and commonMain, joined in one compilation: one compiler run for one target. This one, main, builds your code.

  5. A second compilation, test, joins commonTest with iosArm64's own test source set, to build your tests.

  6. The simulator gets the same pair of its own. Android's compilations are set up by Android's plugin instead, in the same two roles.
