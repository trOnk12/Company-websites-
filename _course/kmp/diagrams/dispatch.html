1. Your coroutine does its network work on Dispatchers.IO: one of Kotlin's own worker threads.

  2. It resumes on Dispatchers.Main. On iOS that's backed by the main queue, so it runs on the main thread, like Android's Looper.

  3. The Swift task waiting for it is cancelled: the user left. But the plain bridge can't pass cancellation across, and the coroutine keeps running. Predict: what stops it?

  4. Owning the scope: the shared view model, whose coroutine is still on Dispatchers.IO, exposes close(), the Swift side calls it when the screen goes away, and the coroutine is cancelled.
