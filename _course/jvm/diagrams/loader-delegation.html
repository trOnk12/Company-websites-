1. Code calls one.loadClass("Greeter"). A class loader is an object that finds class files and turns them into classes. one doesn't look yet: it asks its parent, app.

  2. app asks its parent, platform, which asks the bootstrap loader built into the JVM. This is parent delegation: the request goes up first.

  3. Each parent looks in its own places: bootstrap and platform hold JDK classes, app the class path, the folders and jars given with -cp. None has Greeter; the answer comes back down.

  4. Only now does one look in its own folder, plugin-out, and create Greeter from the file. one is Greeter's defining loader.

  5. A second loader, two, gets the same request and has the same folder and parent. Predict: does it get the same class?

  6. No: the parents still say no, so two defines its own Greeter from the same bytes. Same name, two classes; casting between them fails.
