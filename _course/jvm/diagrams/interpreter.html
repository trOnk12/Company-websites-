1. score(3, 4) starts in HotSpot's template interpreter. It reads the first opcode, iload_0, and jumps to that opcode's template, a small piece of machine code that copies slot 0, the 3, onto the operand stack.

  2. Then the next opcode, iconst_2: read it, jump to its template, which pushes 2. Every instruction repeats the same three things: read, jump, work on the stack.

  3. imul's template multiplies the two values and leaves 6. Five more instructions to go. Predict: how many template jumps does one call of score cost?

  4. Eight, one per instruction, on every call. The interpreter also adds one to score's invocation counter, so HotSpot can tell which methods are called often.

  5. When the count is high enough, a compiler turns all of score into machine code in the code cache. Calls then run it directly: about 2 nanoseconds instead of 19 in the runs above.
