1. On Android, kotlinc still writes class files: the same stack bytecode as in module 2. Adding two locals takes two loads and an add.

  2. d8 converts all the class files into DEX, Android's bytecode, in classes.dex. Its add-int names three numbered registers instead of using a stack (the reference's example).

  3. On the way, d8 rewrites features Android's runtime can't run as written, such as invokedynamic lambdas, which have no LambdaMetafactory on a phone: desugaring.

  4. The APK goes to the phone. Predict: does the phone ever load a class file?

  5. No. ART runs DEX, at first with an interpreter. Its JIT compiles hot methods while the app runs and records them in a profile file.

  6. Later, dex2oat reads that profile and compiles those methods AOT, ahead of time, into machine code, so the next launches start fast.
