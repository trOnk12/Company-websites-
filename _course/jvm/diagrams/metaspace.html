1. A plugin, as in puzzle 13: a loader object and a Greeter object. Objects live on the heap, the memory the garbage collector manages (puzzle 3).

  2. The class itself, its methods, bytecode and constant pool, lives in metaspace: memory outside the heap that HotSpot asks the operating system for, in a chunk owned by its defining loader.

  3. Drop the plugin. Nothing reaches the loader, its object or its class, so the collector can reclaim them all: class unloading.

  4. Now the app keeps one Greeter object in a list. Predict: can class Greeter be unloaded?

  5. No. The object reaches its class, the class reaches its loader, and a class can only be unloaded together with its loader.

  6. Repeat for each plugin load and metaspace only grows. With a 32-megabyte limit, this run failed after 5,310 plugins.
