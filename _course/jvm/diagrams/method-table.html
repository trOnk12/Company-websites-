1. use(c) compiles to invokevirtual Counter.next whatever c holds. Here c may hold a Counter or a Loud, which overrides next.

  2. When HotSpot sets up a class, it builds its method table: one entry per method a subclass could override, pointing to the code to run.

  3. Loud's table starts as a copy of Counter's. Overriding next replaces that one entry, in the same position.

  4. The call reaches a Loud object. Predict: which entry is read, and which code runs?

  5. The receiver's class gives the table, and next's position gives the entry: v + 10. No search through parent classes, whatever the depth.

  6. A final method that overrides nothing gets no entry at all: HotSpot can call it directly. The bytecode still says invokevirtual.
