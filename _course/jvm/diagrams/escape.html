1. As written, every call of scoreOf allocates a Stats on the heap, and the local stats holds a reference to it.

  2. C2 compiles main's loop with scoreOf, the constructor and score() inlined, so it sees every use of that reference. Predict: does the object need to exist?

  3. Escape analysis: the reference is never stored, returned or passed to a call that wasn't inlined. It is only used to read two fields.

  4. So C2 applies scalar replacement: it keeps visits and stars as plain values in the loop and drops the allocation. The heap never sees a Stats.

  5. Add last = stats: the reference leaves through a static field, so the object escapes and is allocated on every call, 24 bytes each.
