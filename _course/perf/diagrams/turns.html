1. Two CPU cores (phones have more). Each runs one thread at a time. Threads that are ready but have no core wait in the run queue.

  2. A's turn is up: the scheduler takes core 0 away and gives it to B, the next in line. A goes back in the queue. That's preemption.

  3. E needs a file from the disk. It isn't ready, so the kernel takes it off the queue: asleep, using no core. Predict: when the file arrives, does E run at once?

  4. No. The kernel wakes E: back in the run queue. It runs only when a core frees up.
