1. The kernel keeps a list of processes and their PIDs. Every process on the host is in one such list, the first one. A list like this, private to the processes inside it, is a namespace.

  2. docker run asks for a new PID namespace, inside the first. Its first process, sleep, is PID 1 there, but still 3393 in the host's list: one process, two numbers.

  3. A ps inside lists PID 1 and 71. ps reads /proc, a folder the kernel fills in as you read it, one entry per process; Docker gives the container a /proc for its own namespace.

  4. From inside, kill -0 23807 asks the kernel whether PID 23807 exists. bash really is 23807 on the host. Predict: what does the kernel answer sleep's namespace?

  5. "No such process": a namespace sees only itself and the namespaces inside it. Outward it is blind; inward the host sees everything, so the host's ps lists sleep as 3393.
