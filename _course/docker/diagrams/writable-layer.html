1. Two containers from notes:v1, box and w2, stand on the same read-only layers. Each gets its own upper directory: its writable layer.

  2. box writes /tmp/draft.txt. The file lands in box's writable layer; the image's layers don't change.

  3. w2 runs the same image, on the same machine. Predict: can w2 read /tmp/draft.txt?

  4. No: "No such file or directory". w2's tree is its own writable layer over the shared layers, and box's layer isn't in it.

  5. Stopping and starting box keeps its writable layer: after a restart, draft.txt is still there.

  6. docker rm deletes the container and its writable layer. A new container from notes:v1 starts with an empty one: draft.txt is gone for good.
