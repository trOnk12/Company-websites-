1. Docker puts each container's processes in a cgroup, a control group: the kernel counts what the group uses and holds it to the group's limits. By default box's group has none: it may use all 16 GB.

  2. docker run --memory 64m sets the group's memory limit: 64 MB for all its processes together. sleep uses 0.7 MB of it.

  3. Inside, free -m reports how much memory there is. Predict: will its total be 64 MB, or something else?

  4. 16088 MB: the host's whole memory. free reads /proc, which no namespace and no cgroup changes, so a program that sizes itself from it plans for memory it can't have.

  5. tail keeps taking memory. At the line the kernel can't free enough, so it kills a process in the group: tail. Docker reports exit code 137.

  6. --cpus 0.5 sets a CPU quota: 50 ms of processor time in every 100 ms period. Used up early, the group waits for the next period, however idle the processors are.
