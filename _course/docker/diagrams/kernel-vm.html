1. A process can't reach a file, the network or another process by itself. It asks the kernel, with a system call: open this file, start that program. sleep's calls go to the host's kernel, Linux 6.18.44.

  2. uname -r asks the kernel which version it is. Predict: run inside the Alpine container, does it print the host's kernel version, or one that came with Alpine?

  3. The host's: 6.18.44-fc-v726, exactly what the host itself prints. The image brought Alpine's files, not a kernel. Every container on this machine calls this one kernel.

  4. Compare a virtual machine, a VM: a whole pretend computer that boots its own operating system, with its own kernel. Its app's system calls go to that kernel, not to the host's.

  5. Below the VM runs a hypervisor: the program that runs VMs and keeps each one behind its own pretend hardware. A VM is separated by that hardware boundary; containers only by the kernel they share.

  6. On a Mac or Windows laptop, and with Docker Desktop even on Linux, Docker runs a small Linux VM, and your containers run inside it, on its Linux kernel. The Mac's own process list never shows them.
