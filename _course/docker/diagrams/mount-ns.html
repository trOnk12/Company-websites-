1. All files sit in one tree that starts at /. A mount attaches a set of files, such as a disk, to a folder in that tree. On the host, / comes from its disk, and /etc/os-release says Ubuntu.

  2. unshare --mount starts a shell in a new mount namespace: its own list of mounts, starting as a copy of the host's. For now both sides see the same files.

  3. Inside, the shell mounts a tmpfs, a filesystem kept in memory, on /tmp/demo and creates a file, inside. Predict: what does the host's ls /tmp/demo print?

  4. Nothing: that mount is only in the new namespace's list. The host's /tmp/demo is still the empty folder on its disk.

  5. Docker goes further: in the container's namespace, Docker's runtime calls pivot_root: the image's files go to / and the host's are unmounted. That's the container's root filesystem: /etc/os-release now says Alpine, and the host's files aren't in its tree at all.
